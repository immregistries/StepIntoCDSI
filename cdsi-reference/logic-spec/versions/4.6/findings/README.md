# Findings

Formal, individually-tracked records (Phase 9 of the plan) for real, independently-verified issues found while documenting this version - each is its own `SPEC-4.6-<NNNN>/` directory with a `finding.yaml` (machine-readable, validated by `logic-spec validate` against `schemas/finding.schema.json`) and a `finding.md` (human-readable narrative). See `../../../../README.md`'s "Reporting an ambiguity or a suspected mismatch" for the full workflow, categories, and how to allocate the next id.

Seven findings exist so far (`SPEC-4.6-0001` through `SPEC-4.6-0007`), all `status: open` pending human review - most significantly `SPEC-4.6-0001` (Section 7.3's contraindication logic is essentially unimplemented) and `SPEC-4.6-0002` (the shared `LogicTable.evaluate()` mutual-exclusivity check is disabled). None are fixed yet, per standing project direction: this is a demonstration/reference system, and clinical-logic fixes are a deliberate later pass once the documentation and testing system is complete.
