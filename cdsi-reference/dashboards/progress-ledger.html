2026-09-08 - Phase 21 - Role B Round 8 - EvaluateVaccineConflict's Dead Live-Virus Conflict Window reviewed

The eighth Role B round, and the first in this whole pass to actually move the FITS suite. EvaluateVaccineConflict's live-virus conflict window was effectively dead code in any normal chronological history: its per-previous-dose loop scanned doses after the current one instead of before, a copy-paste bug always collapsed the conflict end date to the begin date, the begin boundary was exclusive instead of the documented inclusive, and matching ignored the conflicting vaccine type. Fixing all four flipped 14 real FITS cases (3 distinct scenarios - two MMR-after-MMR-too-soon, one Varicella - all from standard age-based routine schedule test plans) from FAIL to PASS, with 0 regressions. Full cdsi-engine suite: 179 -> 171 failures (down exactly 8). FITS suite: 3364 -> 3378 passed (68.7% -> 69.0%). See SPEC-4.6-0015.

2026-09-08 - Phase 21 - Role B Round 7 - Unadjusted Recommended Date Falling Back to Wall-Clock Now reviewed

The seventh Role B round: FORECASTDT-2's ordinary no-earliest-age/ no-earliest-interval fallback read the wrong (empty) forecast list and silently returned wall-clock "now" instead of the series' own earliest date - the ordinary case for the majority of series doses, meaning the recommended date changed every day the engine was run. Fixed by calling the class's own already-correct computeEarliestDate() instead. Confirmed against real FITS data: 25 real cases (5 distinct Polio scenarios) had their computed output genuinely change from a run-date-dependent value to a stable, patient-derived one - though none flip pass/fail, since each has its own separate, unrelated defect. Full cdsi-engine suite: 180 -> 179 failures (down exactly 1), 0 regressions. FITS aggregate counts unchanged (3364/1531/1), verified case-by-case per the SPEC-4.6-0013 lesson. See SPEC-4.6-0014.

2026-09-08 - Phase 21 - Role B Round 6 - CALCDTINT-8 Dead Code and Self-Referencing Regression reviewed

The sixth Role B round, and the first attempted specifically to move a FITS case - it didn't, but the investigation is the story worth recording. CALCDTINT-8 was effectively dead code (a missing null check threw a silently-swallowed NPE every time) and the loader never parsed Supporting Data's multi-CVX <fromMostRecent> list. A first fix attempt caused a real 20-case FITS regression; root-caused via direct engine inspection to a missing lower bound letting a dose reference itself as its own "most recent" reference date - not the extraneous-dose theory first suspected, which had zero actual effect. Extended into unit 6.10 (SatisfyTargetDose) with explicit project-owner approval, adding a new VaccineDoseAdministered.evaluatedAgainstTargetDose link rather than reusing fields other steps depend on staying null. Net FITS effect: a strict no-op (0 cases changed either direction) - the 13 cases that appeared to improve mid-investigation were themselves an artifact of the self-reference bug, not a real fix. Full cdsi-engine suite: 182 -> 180 failures (down exactly 2), 0 regressions. See SPEC-4.6-0013.

2026-09-08 - Phase 21 - Role B Round 3 - EvaluateAge's Absolute-Minimum-Only Age Window Crash reviewed

The third Role B round, and the first to surface a genuine specification-level gap rather than a code/spec mismatch: Table 6-14 gives Minimum Age Date and Absolute Minimum Age Date the same flat 01/01/1900 default, applied independently, which Table 6-15's rule grid cannot always resolve - a target dose with an absolute minimum age but no minimum age crashed the engine with an NPE on 5 real bundled Pneumococcal series doses. Filed as SPECIFICATION_DEFECT and explicitly flagged for CDC/CDSi review rather than treated as settled by this project's own fix. Reviewed and approved a pragmatic resolution: fall the minimum age date back to the absolute minimum age date when only the latter is defined. Unit 6.4: 19/1 -> 20/0 green/red. Full cdsi-engine suite: 188 -> 187 failures (down exactly 1), 0 regressions. FITS suite unchanged (3364/1531/1 identical both sides) - none of the 4896 bundled fixtures reaches the affected input shape. See SPEC-4.6-0010.
